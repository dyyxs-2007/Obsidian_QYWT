## 2. 路径环节一：`UICollectionViewCompositionalLayout` 全局底部 Footer 与 `280pt` 预触发

- **源码位置**：[SPHomeViewController.m:L31-L82, L268-L325, L632-L644](file:///Users/dyyxs/项目/Spotify/Spotify/Modules/Home/SPHomeViewController.m#L268-L325)
- **如何给拥有十几个横向滚动 Section 的 CompositionalLayout 挂载一个统一的底部加载条？**
  如果给每个 `NSCollectionLayoutSection` 挂 Footer，那么每个横向卡片行底下都会出现一个 Footer；正确的做法是在外层 **`UICollectionViewCompositionalLayoutConfiguration` 的 `boundarySupplementaryItems`** 上注册全局底部补充视图 `SPHomeGlobalFooterKind` ([L269-L275](file:///Users/dyyxs/项目/Spotify/Spotify/Modules/Home/SPHomeViewController.m#L269-L275))：
  ```objc
  UICollectionViewCompositionalLayoutConfiguration *config = [UICollectionViewCompositionalLayoutConfiguration new];
  NSCollectionLayoutSize *footerSize = [NSCollectionLayoutSize
      sizeWithWidthDimension:[NSCollectionLayoutDimension fractionalWidthDimension:1.0]
             heightDimension:[NSCollectionLayoutDimension absoluteDimension:56]];
  NSCollectionLayoutBoundarySupplementaryItem *footer = [NSCollectionLayoutBoundarySupplementaryItem
      boundarySupplementaryItemWithLayoutSize:footerSize
                                  elementKind:SPHomeGlobalFooterKind
                                    alignment:NSRectAlignmentBottom];
  config.boundarySupplementaryItems = @[footer];
  ```
- **提前 `280pt` 静默预触发** ([L632-L644](file:///Users/dyyxs/项目/Spotify/Spotify/Modules/Home/SPHomeViewController.m#L632-L644))：
  ```objc
  - (void)scrollViewDidScroll:(UIScrollView *)scrollView {
      SPHomeCategory category = [self currentCategory];
      BOOL hasMore = self.hasMoreByCategory[@(category)] ? self.hasMoreByCategory[@(category)].boolValue : YES;
      if (self.isLoadingMore || !hasMore || self.visibleSections.count == 0) return;

      CGFloat height = CGRectGetHeight(scrollView.bounds);
      CGFloat contentHeight = scrollView.contentSize.height;
      if (height <= 0 || contentHeight <= height) return;
      // 当可视区域底边距离内容总高度底部只剩 280pt（约 1.5 行卡片高度）时，立即触发加载下一页
      if (scrollView.contentOffset.y + height >= contentHeight - 280.0) {
          [self loadMoreSections];
      }
  }
  ```

## 3. 路径环节二：三分类（「全部 / 音乐 / 播客」）独立分页状态机

- **源码位置**：[SPHomeViewController.m:L94-L101, L346-L424, L554-L574](file:///Users/dyyxs/项目/Spotify/Spotify/Modules/Home/SPHomeViewController.m#L379-L424)
- **工程痛点**：
  首页顶部有「全部」「音乐」「播客」三个分类胶囊。用户在「全部」下滑加载到了第 3 页（共 15 个 Section），然后点进「音乐」浏览，再点回「全部」。如果只用一套全局变量 `currentPage` 和 `sections`，切分类时要么丢失之前加载的 3 页数据，要么把「全部」正在加载的第 4 页数据错误地插进「音乐」列表里！
- **三字典隔离设计**：
  ```objc
  @property (nonatomic, strong) NSMutableDictionary<NSNumber *, NSArray<SPHomeSection *> *> *sectionsByCategory;
  @property (nonatomic, strong) NSMutableDictionary<NSNumber *, NSNumber *> *nextPageByCategory;
  @property (nonatomic, strong) NSMutableDictionary<NSNumber *, NSNumber *> *hasMoreByCategory;
  ```
  1. 每个分类拥有自己独立的 `sectionsByCategory[@(category)]`、`nextPageByCategory[@(category)]`（初始为 `@1`）和 `hasMoreByCategory[@(category)]`（初始为 `@YES`）。
  2. 点击顶部胶囊 [`-chipTapped:`](file:///Users/dyyxs/项目/Spotify/Spotify/Modules/Home/SPHomeViewController.m#L554-L574) 时，如果目标分类的 `sectionsByCategory[@(category)]` 非空，**0ms 直接恢复该分类已加载的所有分页**，无需重新请求！
  3. 异步分页回调回来时，先将新分区合并写入 `weakSelf.sectionsByCategory[key] = merged`，然后检查 `if ([weakSelf currentCategory] == category)`——只有当用户当前依然停留在该分类时才更新 `self.visibleSections` 并插入 CollectionView。

## 4. 路径环节三：`slots` 固定槽位数组 + `@synchronized` 解决并发分页乱序

- **源码位置**：[SPNeteaseMusicSource.m:L376-L513](file:///Users/dyyxs/项目/Spotify/Spotify/Data/Netease/SPNeteaseMusicSource.m#L376-L513)
- **工程痛点**：
  在 `-fetchHomeMoreSectionsForCategory:page:completion:` 中，每一页（`page = 1..6`）都会通过 `dispatch_group_t` **同时并发发出 3 个网络请求**（例如 Page 1 同时请求：`cat=华语`、`cat=流行`、`/toplist` 后段榜单）。
  由于 3 个请求在网络上的响应快慢是随机的，如果谁先返回就往 `NSMutableArray` 里 `addObject:`，不仅会导致多线程同时写可变数组崩溃，而且每次刷出来的 Section 顺序都会乱跳！
- **`slots` 固定槽位归位技巧** ([L395-L505](file:///Users/dyyxs/项目/Spotify/Spotify/Data/Netease/SPNeteaseMusicSource.m#L395-L505))：
  ```objc
  // 1. 预先分配 3 个固定槽位，用 NSNull.null 占位
  NSMutableArray<SPHomeSection *> *slots = [NSMutableArray arrayWithObjects:NSNull.null, NSNull.null, NSNull.null, nil];

  // 2. 每个并发任务绑定自己专属的槽位下标 idx (0, 1, 2)
  void (^loadPlaylistCat)(NSInteger, NSString *, NSString *) = ^(NSInteger idx, NSString *title, NSString *cat) {
      dispatch_group_enter(group);
      [weakSelf.client GET:@"/top/playlist"
                parameters:@{@"cat": cat, @"order": @"hot", @"limit": @10}
                    cookie:cookie
               bypassCache:NO
                completion:^(NSDictionary *json, NSError *err) {
          NSArray<SPPlaylist *> *pls = [SPNeteaseParser playlistsFromArray:json[@"playlists"]];
          if (pls.count > 0) {
              SPHomeSection *sec = [SPHomeSection new];
              sec.title = title;
              sec.style = SPHomeSectionStyleCard;
              sec.items = pls;
              // 3. 加锁按固定槽位下标 idx 写入，不论谁先返回，位置永远固定！
              @synchronized (slots) { slots[idx] = sec; }
          }
          dispatch_group_leave(group);
      }];
  };

  // 4. 在 dispatch_group_notify 中按 0 -> 1 -> 2 顺序过滤掉未成功的 NSNull.null
  dispatch_group_notify(group, dispatch_get_global_queue(QOS_CLASS_USER_INITIATED, 0), ^{
      NSMutableArray<SPHomeSection *> *result = [NSMutableArray array];
      for (id obj in slots) {
          if ([obj isKindOfClass:SPHomeSection.class]) {
              [result addObject:(SPHomeSection *)obj];
          }
      }
      BOOL hasMore = (page < 6);
      completion(result, hasMore, nil);
  });
  ```

## 5. 路径环节四：`performWithoutAnimation` + `insertSections:` 无闪烁增量插入

- **源码位置**：[SPHomeViewController.m:L407-L420](file:///Users/dyyxs/项目/Spotify/Spotify/Modules/Home/SPHomeViewController.m#L407-L420)
- **为什么不用 `[self.collectionView reloadData]`，而且为什么要在 `performBatchUpdates` 外面包一层 `[UIView performWithoutAnimation:]`？**
  1. 如果在用户正手指滑动或惯性减速滚动 (`isDecelerating`) 时调用 `reloadData`，`UICollectionView` 会重建所有可见 Cell，导致上方已经显示好的封面卡片闪动，甚至打断滚动动量。
  2. 如果直接调用 `[collectionView insertSections:added]`，UIKit 默认会对新增的 Section 和底部的 `SPHomeLoadMoreFooterView` 执行交叉飞入与位移过渡动画，在快速滑动时底部 Footer 会出现明显的上下弹跳残影。
  3. 用 `[UIView performWithoutAnimation:^{ ... }]` 包裹 `performBatchUpdates:insertSections:` 后，CollectionView 只在底层静默扩展 `contentSize` 并挂载新 Section 的布局属性，用户手指继续往下滑时新分区就像原本就在那里一样自然滑入视野！
