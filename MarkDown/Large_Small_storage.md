# <font color=pink>大/小端存储的概念</font>
 > 在真正了解大小端的概念前，让我们来捋一捋有关**内存单元**和**内存地址高低**，对于我们理解大小端的本质有着巨大的帮助
#### 1. 内存地址
内存地址数值上的本质其实是无符号整型，由于计算机中的**存储系统是线性的**，所以我们所存入的数据也是在内存中线性排布的，我们就可以用一串无符号整形来标记内存中的各个位置，将这些**无符号整型称为内存地址**；计算机使用<u>十六进制数来表示这些内存地址</u>，将计算机中的内存空间按顺序排列并为其用十六进制数编号， 
> 例如在一个32位计算机中，地址范围由低到高从0x00000000到0xFFFFFFFF

这样就可以方便的让CPU对应查找和写入数据
#### 2. 内存单元&&有效字节
对于大多数现代计算机而言，***一个字节就是内存的最小单元***，一个字节(byte)由八个比特(bit)组成，而这个性质就决定了一个内存单元至多存储着2^8这么多种状态，可以表示出256个数字，当然，这远远不够，所以这就需要我们在储存较大数据时使用***多个字节去并行表示***
> 例如32位整数0x12345678，由于最小单元是八个二进制位组成，所以要将该整数拆分为四份0x12，0x34，0x56，0x78**连续的**储存在不同的字节中

在这些存储数据的不同的字节中，根据其储存数据在原本数据中的**位权高低**，将储存了*高位权数据的字节称为高位有效字节*，反之将储存了*低位权数据的字节称为低位有效字节*

##### 由于储存数据的各个字节地址也有高低，由此我们引出了大端存储和小端存储的概念

## 大端存储：
### ***最高有效字节存储于最低内存地址***
如何理解这句话？我们用一张图表来解释：
- 以0x12345678的储存为例

|0x1000(低地址)|0x1001|0x1002|0x1003(高地址)|
|:-:|:-:|:---:|:---:|
|<font color=orange>0x12(高位字节)|0x34|0x56|<font color=green>0x78(低位字节)|

可见大端存储的设备将一个数据按位权从高到低放置到了内存由低到高的字节上

## 小端存储：
### ***最低有效字节存储于最低内存地址***
同样以一张图表来理解：
- 仍以0x12345678的储存为例

|0x1000(低地址)|0x1001|0x1002|0x1003(高地址)|
|:-:|:-:|:---:|:---:|
|<font color=green>0x78(低位字节)|0x56|0x34|<font color=orange>0x12(高位字节)|

> 当然无论采取大端还是小端存储的方式，当需要读取原数据时计算机会按照初始读入顺序来解读顺序，否则解读出来的数据可能不是我们想要的

# <font color=pink>大/小端存储的优点比较</font>
- #### 大端存储的优势：
    1. 大端存储在内存地址上由低到高存入位权由高到低的数字，十分符合<font color=red>人类</font>书写数字从左向右（从位权高至位权低）的书写风格，更接近*人类的自然想法*。
    2. 大端存储将最高位权存于低地址，因此在进行一个数的符号判断时只需要读取最低内存地址的值即可知道**符号位上的状态**
    3. 大端存储也可应用于一些加密算法，校验算法之中
- #### 小端存储的优势：
    1. 小端存储将低位权存于低地址的做法十分符合<font color=red>CPU</font>的运算逻辑，我们知道CPU的底层是加法器，而<u>加法器就是从最低位开始运算</u>，而从**更近**的低地址直接进行低位的加减运算显然十分便捷
    2. 小端存储可以十分快速的做到某些格式转换，例如int类型数据直接转为char类型数据，只需要获取int类型的最低位八个数据，**直接在低位访问省去了CPU访问高位所耗费的时间**
    3. 小端存储在一些需要频繁进行位运算如按位与和按位或的时候展现出优良的性能，可以**快速地对最低有效数字进行访问和操作**
    4. 小端存储也可以在一些需要**精简体量和减少资源**的领域（如嵌入式系统）提高性能
- ##### 比较以上两点不难看出大端存储更偏向于人类对计算机朴素的理解，小端存储更倾向于机器的逻辑判断，二者各有其发挥长处的领域。

# <font color=pink>一个简单判断设备大/小端存储的方法</font>
上代码：
```c
#include<stdio.h>
int main() {
	int i = 1;
	char* ptr = (char*)&i;
	if (1 == *ptr) {
		printf("小端存储\n");
	} else {
		printf("大端存储\n");
	}
	return 0;
}
```
> 运行结果如图所示，可见我的编译器所采用的是小端存储

[![pVXeief.png](https://s21.ax1x.com/2025/10/23/pVXeief.png)](https://imgchr.com/i/pVXeief)
- ###### 这个程序判断大小端的原理是先声明一个int类型的空间，占四个连续的字节，我们将这个空间的**最低位**放入一个1，再将这个空间的首地址通过强制转换赋予给了一个char类型**指向单字节的指针**，这样<font color=red>char指针在读取的时候只会读取最低内存地址的一个字节中的值</font>，如果是1就说明这个**存储在最低有效字节的1**存放的位置是**最低内存地址**，也就对应了我们小端存储的概念，反之则说明是大端存储。

# <font color=pink>大/小端存储的生态区别</font>

1. 大端存储在早期的CPU设计中较为受青睐，但如今的CPU多采用小端存储的方式，代表是intel所出品的CPU
2. 在一些编程语言中底层采用了大端存储的方式，如java，保证了其数据传输的一致性
3. 在网络通信领域大端存储对转换为大端字节序有着直接而重要的帮助

# <font color=pink>扩展：网络字节序 与 大/小端字节序</font>
- 大/小端字节序指的是**在通信时输出数据的排列顺序**，在某种程度上与大小端存储的读取一样，而由于这种顺序的差异，有时不同的设备间将不能做到精准通信，于是有了网络字节序的规定。
- 网络字节序与大小端存储有着密不可分的联系，在网络通信传输中，**数据从最低内存地址开始读取发送**，而这就牵扯到大小端存储，UDP/TCP/IP协议规定:把接收到的第一个字节当作高位字节看待，也就是说，**储存于最低内存地址的数据应该是初始数据的最高有效字节**，这与我们的大端存储规则相同

# <font color=pink>总结：</font>
大端与小端存储是计算机中两种相反的储存方式，由于不同的储存方式衍生出不同的应用场景，在如今的通信与信息领域创造了重要的价值。
