# 从一个问题的引入
- [力扣题目链接](https://leetcode.cn/problems/combinations/)
- 问题如下:
> 给定两个整数 n 和 k，返回范围 [1, n] 中所有可能的 k 个数的组合
> 例如：给出一个n = 3，k = 2， 你需要返回的是 {{1, 3}, {1, 2}, {2, 3}}
- 对于我们给出的这个例子，简单思考一下，根据我们以前所学的写法，似乎只需要写两层for循环分别来遍历每一个数字就可以了，我们这样朴素的想法确实是可以实现的
- 但是，当k的值增大了以后呢？为了返回k个数的组合，我们需要**k个for循环的嵌套**，虽然不是说完全不能实现，但是一个代码写出几十几百个嵌套for多少是有些惊世骇俗了
- 那么有没有一种方法可以不用写出很多嵌套的for循环又能解决这个问题吗，有的有的，这就需要我们的回溯算法登场了
![屏幕截图 2025-11-14 194605.png](https://youke1.picui.cn/s1/2025/11/14/6917166c79488.png)

- 我们先给出这个问题用回溯算法解决的代码，看不懂没关系，我们会在后面的讲解中逐个击破并弄明白它的原理
```c
#include<vector>
#include<iostream>
using namespace std;
class Solution {
public:
	vector<int>path;
	vector<vector<int>>result;
	void Back_Tracking(int n, int k, int index) {
		if (path.size() == k) {
			result.push_back(path);
			return;
		}
		for (int i = index; i <= n; i++) {
			path.push_back(i);
			Back_Tracking(n, k, i + 1);
			path.pop_back();
		}
	}
};
int main() {
	Solution nums;
	nums.Back_Tracking(3, 2, 1);
	for (int i = 0; i < nums.result.size(); i++) {
		for (int j = 0; j < nums.result[0].size(); j++) {
			printf("%d", nums.result[i][j]);
		}
		printf("\n");
	}
}
```
> 无论k为多少时均可以以这个长度解决，无需反复的嵌套循环，这也就是回溯算法的优势
> 我们将在后面的讲解中分析各个模块的作用，不必心急
# 回溯算法的简述
## 所谓回溯的含义
回溯算法，顾名思义就是可以在做了决策之后退回到上一步的算法，就像是走迷宫，当你发现走进一个死胡同时，需要退回到上一个分岔路口，而不是从入口再进入重走一遍
## 如何做到回溯
- 为了实现一个回溯的动作，我们首先要思考回溯的前提条件是什么
- 其实就是我们需要保留着上一次选择时的入口，当这一层遍历完之后回溯到这个路口，进行一种全新的选择
### 为什么for循环不能回溯？
- 其实对于for循环来说，它并不保留上一次选择的入口，自然无法退回去了，就比如开篇的举例中，返回的数组中第一个数字该选什么，是1~3中的谁？***当for循环敲下的那一刻，你就必须给它一个初始的值***，那怎么做到选其他数呢？就只能再套一个for循环来重新选择了

### 回溯算法能回溯的原因：
- 不知道你有没有注意到，开篇的代码中， Back_Tracking()函数在内部被递归地调用了，这其实就是它能做到回溯的关键
> 那为什么递归一下就能回溯呢
- 其实这就像是当你在进行着一个选择的时候，突然开了一道能传送回来的传送门，你可以在这扇门后面再进行第二个选择，当你选完知道结果了以后， 递归结束，顺着门回到第一个选择
- 这时候你就可以尝试第一个选择的其他选项了
（当然<u>，在传送门后面还可以有第二个传送门</u>，这样的递归就避免了反复嵌套的工作量）
> 听完是不是对回溯有了一点点朦胧的感觉，没关系，这种感觉会在后面的深入中一点点加深

## 回溯算法中的循环
- 上面说了怎么选的问题，那么我们究竟是怎么是实现“选数”这一功能的呢？答案是使用一个循环：
<font color=red>for循环控制每一层的选数，递归控制纵向的深入（选完一个后的下一次选数）</font>
- 拿上面的树状图2举例，我们看到第一层的三个路径各选了不同的数，我们用for循环实现，在for的内部，先将选到的数放入结果集里，然后开始递归
- 注意这时候递归后，还要进行一次for循环，但由于我们递归时可以传入一个下标来控制下一个for的起点，比如取了1之后的递归for从2开始遍历
- 当1，2都被放入结果集后，再递归就会先将已经得到的结果存入总结果集，再直接返回，返回了就要将已经收获的结果逐一弹出，这一步在每层递归之后会实现

# 回溯算法的一般结构
回溯算法的一般模板：
1. 声明一个全局的path和result分别储存路径结果和总结果集（当然设置在你的函数里面其实也可以，只是每次都需要传入传出十分麻烦，故不推荐）
```c
vector<int>path;
vector<vector<int>>result;
```
2. 写Back_Tracking()函数（包括参数和返回值（接下来会讲））
`void Back_Tracking(int n, int k, int index) {`
- 注意由于我们是直接对全局的数组进行修改，所以不需要返回值，直接写void就好
3. 由于我们需要进行的是递归，所以在函数中先写下终止条件：
    ```c
    if (path.size() == k) {
            result.push_back(path);
            return;
        }
    ```
    注意这里的终止条件要根据题目来决定
    本题中，需要2个数字就够，所以当收集到两个数即path中存了两个数就放在总结果集里
4. （回溯的核心区域来了）

    - for循环部分，先上代码, 我们后面对其逐行解释：
    ```c
    for (int i = index; i <= n; i++) {
            path.push_back(i);
            Back_Tracking(n, k, i + 1);
            path.pop_back();
        }
    ```
- 第一行：for循环，从我们传入的index（数组下标开始），你可以想象为从当前数层的index下标的数开始向后遍历
![b78ac7cc11e94667840d0256542e65b2.png](https://youke1.picui.cn/s1/2025/11/14/69173021b557f.png)
1. 取1了之后就要进入递归，并且更新递归中的for的初始下标为后面一个，就如同图中箭头右边的部分，在这个递归的for里进行和第一个相似的操作
- 第二行：path.push_back(i):
1. 首先这行代码的意思是在path数组里加入i这个值，这个比较好理解，结合我们在上一行说的，先取数字再进行递归，我们要先把取的数字放在path数组里
2. path是存储每一次取值的结果，而result是所有不同的path的总结果集，如图中，每次取的过程都有一个箭头，表示的是应该取到path的值，就像一条条路径，表示了每次取的值
- 第三行：递归本函数：
1. 先讲解Back_Tracking()函数的参数问题，为了我们在递归时能实现不重复选或者需要重复选等步骤，需要传入一些数组下标，在本例中，index代表了函数中for循环的遍历起始点，将每一个index后面的可能值放入path数组
2. 本题为了不重复选取结果，**需要从选取的数的下一个数字开始**，于是我们传入当前的下标+1进入递归
3. <u>此时在递归中的函数，它的index是上一层选的数的下一个下标，它的for从这里开始往后遍历，完美的避开了重复问题</u>
- 第四行：path.pop_back():
1. 这一步可能是新手最容易疑惑的一步，为什么刚刚加进去的数，这下又给弹出了呢？那我到底有没有收集到这个数呢？
2. 这还要从上一步递归开始讲起，递归时的path数组已经储存了i的值，那么在递归中的多次调用之后，（如果满足存入结果条件的话）***一定会在结果中存入包含这个i的path数组***
3. 当那些很多的递归调用结束后表示什么？***表示了当初被存进去的那个初始的i的所有可能情况已经都检查过并且上传给result数组了***，那么该用for循环进行下一个操作了
4. 不过在这之前，path数组是不是还存这之前放进去的1，如果不把1给踢出去，在后面以2开始的遍历中就会存在1，就和我们前面分析过“包含1的所有情况已经被检查过”重复了，就会导致严重的重复
5. 所以在递归的调用后，<font color = red>要将当前所有改变的事情复原，进行for的下一个元素遍历</font>
![862c9374e3ee1a58d6fb3f81a01ca08b.png](https://youke1.picui.cn/s1/2025/11/14/6917365c4ae6f.png)

# 回溯算法的三板斧：
## 确定回溯函数的参数：
1. **确定是否需要下标的改变**，这个影响的是储存的结果是答案的组合还是答案的排列，如果需要，就添加index参数
2.  部分题目需要传入数组来填入path，并不是所有回溯算法问题结果元素都是连续增长的正整数
3.  是否需要传入sum变量和，比如需要求哪些元素集合的求和等于或者大于给定值
4.  传入给定的一些必要参数，例如求和的目标值等

真正在实战中不妨先写下几个必要的参数，在实际的递归调用中自然的就会直到哪些参数缺少，哪些参数多余

## 确定回溯函数的终止条件：
这也是递归书写的重要一环，在回溯算法中除了处理终点情况外，还要收集path的结果
1. 终止条件有些情况下必须加return，而有的地方是没必要，但是为了统一与理解，我建议都加
2. if的条件选择中，如总和等于给定值时收集入result并返回
3. 如path存入的数目等于需要的数组长时储存并返回
- 这些收集的条件是它作为递归函数终止条件的一些子集，所以还要对其本身的终止做一判断（当然不判断也行，仅限控制下标系列的回溯算法，因为到最后会不进入for循环，就不能进行无休止的递归）

## 确定回溯函数中每个for循环的下标，递归前的操作和递归后的回溯
- 在递归前所做的一切操作，最终在递归结束后都要原封不动的返还回来，为了保证for循环遍历到下一个的时候的结果集不受影响
- 对于普通组合问题，只需要放入path数组
- 对于求和问题，要声明变量sum，前面给sum加上当前值并传入下一层递归，后面要把sum减去当前值

# 例题实战
## 组合总和III
[力扣题目链接](https://leetcode.cn/problems/combination-sum-iii/description/)
- 题干：
> 找出所有相加之和为 n 的 k 个数的组合，且满足下列条件：
> 只使用数字1到9
> 每个数字 最多使用一次 
> 找到所有可能的有效组合的列表 。该列表不能包含相同的组合两次

- 分析 ：题目中出现组合，而且是k个数的组合，使用传统方法必然是无穷无尽的嵌套循环，工作量过于恐怖，于是采用回溯算法
- 确定Back_Track()函数的参数，我们注意到，题目要求有一个和的目标值为n，所以函数参数要有n，sum保存总和，由于每个数组最多使用一次，所以要传入下标index防止重复选数，由于需要k个数作为收获结果的条件，还要传入k
所以最终的参数为：n, k, sum, index
```c
void Back_Tracking(int tar, int k, int sum, int index) {
```
- 确定函数的终止条件：由于总和需要为n且个数为k，所以k == path.size()是终止条件，而题目又要求总和为n，所以要嵌套入n == sum作为收获结果的条件
```c
if (path.size() == k) {
    if (sum == tar) {
        allin.push_back(path);
    }
    return;
}
```
- 由于数字不能重复，所以需要从传入的index开始遍历
- 确定递归前要进行的操作：由于题目要求返回数字，所以先把i加入path里面，并且收获条件和sum有关，所以要给sum先加上i
- 由于之前提到的“改变什么就要变回来”的原理，递归之后要给sum减去i，把path的最后一个弹出
```c
for (int i = index; i <= 9; i++) {
    path.push_back(i);
    sum += i;
    Back_Tracking(tar, k, sum, i + 1);
    sum -= i;
    path.pop_back();
}
```
最后组合起来就是：
```c
class Solution {
public:
    vector<int>path;
    vector<vector<int>>result;
    void Back_Tracking(int tar, int k, int sum, int index) {
        if (path.size() == k) {
            if (sum == tar) {
                result.push_back(path);
            }
            return;
        }
        for (int i = index; i <= 9; i++) {
            path.push_back(i);
            sum += i;
            Back_Tracking(tar, k, sum, i + 1);
            sum -= i;
            path.pop_back();
        }
    }
    vector<vector<int>> combinationSum3(int k, int n) {
        Back_Tracking(n, k, 0, 1);
        return result;
    }
};
```

## 子集问题
[力扣题目链接](https://leetcode.cn/problems/subsets/description/)
- 题干：
> 给你一个整数数组nums，数组中的元素互不相同，返回该数组所有可能的子集（幂集），解集不能包含重复的子集

例如：nums为{1， 2， 3}
你需要返回的是：{{}, {1}, {2}, {3}, {1, 2}, {1, 3}, {2, 3}, {1, 2, 3}}

- 可见题目要求我们返回这个nums数组的所有子集
- 遇到这样要求我们探索每一个结果的问题时首先想到回溯算法

思路如下：
1. 我们回想一下开篇的案例，我们返回的是固定两个数的数组，这是因为收集结果的条件是path数组的元素达到两个
2. 而在本题中需要我们返回的数组不仅囊括多个数字，每个结果的元素数目也不同，难道我们要设置很多个终止条件来收集结果吗？
3. 其实我们只需要取消终止条件，直接在函数内收集结果即可，不妨想一想，当第一次进入back函数，此时path数组为空，先把它加入结果集是不是就有了第一个的{}，而在for循环内我们将第一个元素1加入path数组，这时候进入递归，path再次被收集，此时就出现了结果集的第二个元素-{1}
4. 我们再来回顾一下定义back函数的时候的参数问题，由于这个题并不要求我们求数字总和，所以不需要sum等，而且也需要我们不选取重复的元素，所以也需要index参数来改变下标
5. 在for循环中我们应该遍历当前下标的元素到最后一个，由于只需要返回数字，这里直接把i传入path而不需要其他操作
6. 递归调用时传入下标为当前下标+1防止重复选
- 结合代码好好理解一下上面这段话：
```c
class Solution {
public:
    vector<int>path;
    vector<vector<int>>result;
    void Back_Tracking(vector<int>&nums, int index) {
        result.push_back(path);//直接收集结果
        //相似的for循环
        for (int i = index; i < nums.size(); i++) {
            path.push_back(nums[i]);
            Back_Tracking(nums, i + 1);
            path.pop_back();
        }
    }
    vector<vector<int>> subsets(vector<int>& nums) {
        Back_Tracking(nums, 0);
        return result;
    }
};
```
- 可能你会十分疑惑，这分明是递归，没有终止条件岂不是要无穷无尽的进行下去了吗？
- 实则不然，注意看这个代码，在每次递归时传入的是i+1，也就是下一个数字的下标，在一次次的递归中，这个index下标一定是慢慢变大的，所以最终一定会大于nums的元素个数，这样就不会进入for循环，也就不会有下一层递归，当前层执行完直接返回上一层的调用
# 回溯算法的循环内去重与递归间去重
> 代码随想录中也将这两种去重称为树枝去重和树层去重，这种解释用树形图解释也十分生动
## 循环内去重与递归间去重的区别：
### 递归间去重
- 什么叫递归间去重，通过前面的接触我们已经了解到回溯算法在执行递归是可以选择是否传入下标来操作开始遍历的元素，这样就可以避免同一个数字被反复取
- 其实我们刚刚举的几个例子都已经用到了这一点

还是以{1， 2， 3}中取两个数为例

- 如果说第一个取了1，递归时正常取到2，此时结果为{1，2}，接着取完一个2之后递归时不改变下标，而是又从头开始遍历，这样就会收获结果为{2，1}，显然这是重复了
- 在刚刚的例题中也说了，这样递归时不改变下标的回溯是解决排列问题的，因为无论从哪个数开始选，第二次选的都是它的补集中的元素，一定存在重复
> 由于前面介绍过这种去重的逻辑，我们这里不过多赘述

### 循环内去重
循环内去重与递归间去重不太一样，我们依旧从一到例题去引入：
[力扣题目链接](https://leetcode.cn/problems/combination-sum-ii/description/)
- 组合总和II
- 题干：
> 给定一个候选人编号的集合candidates和一个目标数target，找出candidates 中所有可以使数字和为 target的组合。
candidates 中的每个数字在每个组合中只能使用一次
注意：解集不能包含重复的组合

例：candidates={10,1,2,7,6,1,5} target = 8
你应该返回{{1，1，6}，{1，2，5}，{1，7}，{2，6}}

- 这道题的灵魂就在于，给定的candidates数组是允许有数字重复的

~~那很多人就会说了:~~数字重复刚刚不也出现了吗，我们不是使用下标移动的方式去重了吗？
- 注意这里的去重，可不是对同一个数字的去重，而是对不同下标的同一个数字去重，观察给的例子中第一个就是1，1，6，出现了两个1，但这两个1可不是一个1被用了两遍，而是选完第一个1，又选了第二个1
- 如果我们使用以前去重的逻辑会发生什么呢？
![屏幕截图 2025-11-15 162734.png](https://youke1.picui.cn/s1/2025/11/15/6918396024682.png)
- 看到出现了两个重复，那么原因是什么呢？我用图解的形式给出1，1，5的重复（1，7同理）：
![a8363c95f029c4298006b207f33c9ffb.png](https://youke1.picui.cn/s1/2025/11/15/69183b1158e01.png)
有没有发现什么端倪？
- 第一次遍历到A1的时候，此时已经把所有包含1的子集都遍历过了，而当for循环继续往前走的时候，遇到B1，它又会以B1为基础重新遍历一遍有B1的子集，这不就重复了吗
- 既然我们刚刚说第一次遍历到1的时候就已经遍历到所有含1的子集了，那么我们去重的逻辑也就呼之欲出了：
- <font color=red>遍历到前面遍历过的相同元素直接跳过</font>
- 这样做不仅遍历了原本应该遍历的元素，同时也防止了相同的数字被遍历
> 现在是不是比较好理解为什么叫循环内去重了吧，目的就是在循环内去掉重复的选取

### 循环内去重的具体实现：
按照我们刚刚的分析，需要实现的是在循环中遇到已经遍历过的元素就跳过
我将会给出两种方法，根据需要自行选择即可：
#### 排序操作
- 注意，为了方便的进行去重，我们需要先将原本的数组排序，这样就可以将相同的数放在一块，当遇到第一个先回溯遍历完包含它的所有结果
- 接着由于把相同的元素放在了一起，如果它的后面还是相同的元素，就continue，到下一个元素，直到遇到不一样的元素
![2ca3d61a113d543b177eb46c370315de.png](https://youke1.picui.cn/s1/2025/11/15/691842d5c3bf8.png)
> 当然并不是说必须要对数组排序了，也可以用哈希表的方式记录遍历过的元素，遇到重复就跳过，这个方法留给读者拓展
#### 下标判断法：
下标判断法的核心代码就是
```c
for (i = index;....) {
    if (i > index && nums[i] == nums[i - 1]) {
        continue;
    }
    ......
}
```
- ok我们来分析一下它的工作原理，在内层的if语句里，首先判断了“i>index”这一步的原因是
1. 当第一层遍历到第一个元素时放入path，接着向下递归，当递归结束后，回到第一层开始遍历到第二个元素
2. 此时如果第二个元素和第一个元素相等，满足nums[i] == nums[i - 1]，同时i也到了index+1，说明遇上重复元素了，于是跳过这种情况
- 为什么这里不是i > 0而是index呢？
- 原因是这样的，如果只是单纯的>0，在第一层取数之和进入递归，就自动的满足了i>0的这个条件，这时候如果下一个就是和第一层相同的元素，就会直接触发跳过，把这种1，1，...的情况漏算了
- 而如果换成i>index，至少能保证把当前for循环开始的第一个元素放进入，并在之后的遍历中正确的跳过相同项
##### 用下标判断解决组合总和II的代码：
```c
class Solution {
public:
    vector<int>path;
    vector<vector<int>>result;
    void Back_Tracking(vector<int>& candidates, int target, int index, int sum) {
        if (sum >= target) {//结果收集（有无外层循环均可）
            if (sum == target) {
                result.push_back(path);
            }
            return;
        }
        for (int i = index; i < candidates.size(); i++) {
            //核心处理循环内重复的代码
            if (i > index && candidates[i] == candidates[i - 1]) {
                continue;
            }
            path.push_back(candidates[i]);
            sum += candidates[i];
            Back_Tracking(candidates, target, i + 1, sum);
            sum -= candidates[i];
            path.pop_back();
        }
    }
    vector<vector<int>> combinationSum2(vector<int>& candidates, int target) {
        sort(candidates.begin(), candidates.end());
        Back_Tracking(candidates, target, 0, 0);
        return result;
    }
};
```
#### judge数组判断法：
- judge数组法原理是建立一个新的数组，该数组元素数目对应给定数组的数目，并初始化所有元素为0，在递归前将当前元素设置为1表示这个元素已经取过

即：`judge[i] = 1`
- 当一个递归结束后，遍历到下一个元素，这时候判断两个元素是否相等，如果相等，再判断前一个元素是否用过，即judge[i - 1]是否为1，如果遍历，就需要跳过，直接continue
judge数组判断法解决组合总和II的代码：
```c
class Solution {
vector<vector<int>> result;
    vector<int> path;
    void backtracking(vector<int>& candidates, int target, int sum, int startIndex, vector<bool>& used) {
        if (sum == target) {
            result.push_back(path);
            return;
        }
        for (int i = startIndex; i < candidates.size() && sum + candidates[i] <= target; i++) {
            // used[i - 1] == true，说明同一树枝candidates[i - 1]使用过
            // used[i - 1] == false，说明同一树层candidates[i - 1]使用过
            // 要对同一树层使用过的元素进行跳过
            if (i > 0 && candidates[i] == candidates[i - 1] && used[i - 1] == false) {
                continue;
            }
            sum += candidates[i];
            path.push_back(candidates[i]);
            used[i] = true;
            backtracking(candidates, target, sum, i + 1, used);
            used[i] = false;
            sum -= candidates[i];
            path.pop_back();
        }
    }
public:
    vector<vector<int>> combinationSum2(vector<int>& candidates, int target) {
        vector<bool> used(candidates.size(), false);
        sort(candidates.begin(), candidates.end());
        backtracking(candidates, target, 0, 0, used);
        return result;
    }
};
```
# 回溯算法的剪枝问题
- 所谓剪枝，就是提前将可以确定不符合条件的情况舍去，我们思考一个问题：
- 在十个数里面选四个数，用回溯算法解决的时候，如果第path的一个数选到了十个数中的第八个，那么还有没有继续选下去的必要呢？
- 答案当然是没有，因为选到第八个数之和不论怎么选，最多再选两个数，凑不够4个数，所以当第一次for循环遍历到第八个数的时候，可以直接跳出循环
- 当然这样的事情在递归的for循环内同样可以发生，比如选了先选了第一个数，递归中第二个数遍历到第九个数的时候，也可以确定不能凑成四个数返回，所以也可以直接跳出
## 剪枝具体实现例子：
- 我们依旧以开篇给出的例子为参考：
> 给定两个整数 n 和 k，返回范围 [1, n] 中所有可能的 k 个数的组合
> 例如：给出一个n = 3，k = 2， 你需要返回的是 {{1, 3}, {1, 2}, {2, 3}}

先前我们已经给出的核心算法（for循环部分）是：
```c
for (int i = index; i <= n; i++) {
            path.push_back(i);
            Back_Tracking(n, k, i + 1);
            path.pop_back();
        }
```
根据我们上面的分析，在n个元素里取k个数，也存在可以剪枝的情况，那我们该怎样剪枝呢？
> n个数中取k个数
- path.size()表示已经放进结果里的个数，那么为了达到要求，我们还需要取`n - path.size()`个数，那剩下等待我们取的数的个数一定要比这个值大或者等于这个数，一旦比这个还小，说明剩下的就不够凑成想要的集合，这个结果就“废了”，而i代表当前在取的数，n代表总数，我们就可以建立出剪枝的方案
- 所以最终我们的剪枝方案就是：
```c
for (...){
    if (k - path.size() > n - i + 1) {
        break;
    }
    path.push_back(i);
    ......
}
```
- 注意此时的右边有一个+1的原因是此时还没把i放进path，所以就相当于是`n - (i - 1)`个数还待取，如果放在pathpush的后面就不用+1
- 同时我们还可以将这个合并到for的循环条件里，一旦不符合这个条件就退出循环，可以起到一样的作用：
```c
for (int i = index; i <= n && k - path.size() <= n - i + 1; i++) {
    ......
}
```
- 当然要注意这里要取原本break条件的反，即>变成<=，因为一个是满足条件触发退出，一个是不满足条件时触发退出
## 剪枝的适用场景
- 上面我们给出的一个剪枝只是剪枝操作中的一个案例，实际的操作要根据题目中的要求灵活变通，简单地讲就是：先用我们的人脑优化，再交给计算机执行
- 剪枝也可以用于很多的场景中，比如n皇后，判断当前皇后位置不合适的时候直接返回，不必搜遍棋盘的每一个位置
- 又比如我们先前描述的两种去重，其实也是一种剪枝，只不过这样的剪枝是我们解决问题所必要的部分，而以上的例子中的剪枝不是必须的，但对我们的算法有着优化作用
# 再探回溯算法本质
1.  回溯算法是一种利用递归遍历所有情况的算法，这个性质与DFS（深度优先搜索）十分相似，都是先探索完一条路径，再回溯的探索下一条路径
2. 但是回溯算法并不能完全等同为DFS，我们可以这样概括地总结：
$回溯算法 = DFS + 剪枝$
# 回溯算法的适用场景
- 从我们给出的各种例子可以看出，解决几乎所有需要遍历所有结果的问题就可以使用回溯算法，这也恰恰证明了回溯算法是一种十分暴力的解决问题的方法，没有那么多拘束
- 同时回溯算法也可以用于解决很多的动态规划问题，毕竟是暴力搜索，，
